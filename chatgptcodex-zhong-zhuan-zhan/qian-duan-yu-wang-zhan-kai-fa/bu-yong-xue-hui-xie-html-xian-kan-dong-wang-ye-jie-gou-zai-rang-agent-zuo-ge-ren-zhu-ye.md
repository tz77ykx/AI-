# 不用学会写 HTML：先看懂网页结构，再让 Agent 做个人主页

用 Agent 做网页，不等于先把自己训练成前端开发者。

你不需要背标签、记 CSS 属性或亲自写 JavaScript。真正需要掌握的是一张“项目地图”：知道内容、样式、交互和图片通常分别放在哪里，出现问题时能描述现象，并让 Agent 在正确范围内修改。

本文的目标不是教你写代码，而是让你能够完成四件事：准备真实内容、给 Agent 交代任务、看懂它改了什么、在浏览器里判断结果是否合格。

本文所说的 Agent，是能够读取和修改当前项目文件、运行项目命令的编程 Agent，而不是只能回答问题的普通聊天窗口。开始前，先新建一个空文件夹，或者选择一个已有项目文件夹，再把它作为 Agent 的工作区打开。Agent 如果不能访问这个文件夹，就无法直接替你完成网页。

## 先看懂网页项目里的各个部分

一个网页项目通常由若干文件和文件夹组成。不同技术栈的文件名会变化，但职责大致相同：

* **项目根目录**：整个项目最外层的文件夹。Agent 应先在这里读取说明、依赖和现有文件。
* **HTML 或页面组件**：负责页面的内容与结构，例如标题、介绍、作品和联系方式。
* **CSS 或样式文件**：负责颜色、字体、间距、布局和响应式变化。
* **JavaScript 或交互逻辑**：负责菜单展开、按钮行为、表单反馈等互动。
* **图片与其他素材**：通常放在专门的资源目录中，并通过文件路径被页面引用。
* **项目说明文件**：记录怎样运行项目、使用什么技术以及有哪些注意事项。

在简单的静态网页里，入口文件经常叫 `index.html`；在 React、Next.js 等项目中，页面可能由多个组件组成。不要预设项目一定是哪种结构，让 Agent 先检查再解释。

你只需要记住这组关系：

```
内容或结构不对 → 检查页面文件或组件
颜色、间距或排版不对 → 检查样式
按钮、菜单或表单没反应 → 检查交互逻辑
图片没有显示 → 检查素材文件和引用路径
手机页面挤在一起 → 检查响应式布局
```

这些判断不是让你亲自修复，而是帮助你把问题准确交给 Agent。

## 你负责决定什么，Agent 负责完成什么

你负责：

* 页面给谁看，以及希望对方看完后做什么；
* 页面要使用的真实姓名、介绍、作品、链接和图片；
* 喜欢的参考方向，以及明确不想要的风格；
* 哪些内容必须保留，哪些信息不能公开；
* 最终页面是否符合你的目的。

Agent 负责：

* 检查项目当前使用的技术和文件结构；
* 创建或修改页面、样式、交互和素材引用；
* 启动本地预览；
* 检查桌面端、移动端和关键交互；
* 运行项目已有的测试和检查；
* 报告修改文件、验证结果和仍未解决的问题。

这个分工很重要：你不需要告诉 Agent 每一行代码怎么写，但必须告诉它结果是什么、边界在哪里、怎样才算完成。

## 第一步：准备内容，不要先碰代码

先把个人主页真正需要的材料放进项目文件夹或整理成一份文档：

* 姓名或展示名称；
* 一句能够说明你是谁的介绍；
* 想展示的经历、项目或作品；
* 希望访客执行的主要行动；
* 联系方式和外部链接；
* 已确认有权使用的头像、照片或作品图；
* 不允许公开的信息。

不要让 Agent 用空泛的营销文案代替真实内容。资料暂时不完整时，让它明确标记缺口，不要自行编造。

## 第二步：先让 Agent 解释项目，再允许它修改

把项目文件夹交给 Agent 后，先发一个检查任务：

```
请先检查当前项目，不要修改文件。

用普通人能理解的中文告诉我：
- 这是空项目还是已有项目
- 当前使用什么技术
- 哪些文件负责页面内容、样式、交互和图片
- 应该怎样在本地预览
- 制作个人主页预计会新增或修改哪些文件
- 开始前还缺少哪些真实内容或素材

不要要求我手写代码。信息不足时先提问，等我确认方案后再开始实现。
```

这一轮的目的不是学习语法，而是确认 Agent 已经读懂项目，没有凭经验猜文件结构。

如果当前是空文件夹，不要让 Agent 立即安装一堆工具。先让它提出最简方案：说明准备使用什么技术、电脑需要什么运行环境、会创建哪些文件、怎样启动和停止预览。你确认后，它再创建项目、安装确实需要的依赖并打开第一版页面。

```
当前工作区是空文件夹。请先提出制作个人主页的最简技术方案。

说明：
- 为什么这个方案适合当前页面
- 需要什么运行环境和必要依赖
- 准备创建哪些文件
- 怎样启动和停止本地预览
- 是否存在更简单、无需额外依赖的方案

先等待我确认。确认后再创建文件、安装必要依赖并启动预览。不要要求我手写代码。
```

如果是已有项目，让 Agent 沿用原有技术、运行方式和组件体系；除非它能说明必要性并得到你确认，否则不要更换框架或重新初始化项目。

## 第三步：先确认页面规则

如果你已经阅读过[《先写 DESIGN.md，再写页面》](xian-xie-design.md-zai-xie-ye-mian-fei-she-ji-bei-jing-de-codex-qian-duan-gong-zuo-liu.md)，可以让 Agent 把页面目标、参考、视觉规则、响应式要求和验收标准保存到 `DESIGN.md`。

没有设计说明时，至少把下面这些事情说清楚：

* 首屏最先出现什么；
* 页面有哪些内容区块；
* 主要按钮是什么；
* 整体参考什么，不复制什么；
* 桌面端和移动端分别怎样排列；
* 哪些颜色、字体、卡片或动效不要使用；
* 需要检查哪些页面和交互状态。

可以直接让 Agent 整理：

```
根据我的真实内容和参考，整理一份可以执行和检查的页面说明。

写清页面目标、内容顺序、视觉方向、响应式变化、禁止事项和验收标准。不要只使用“高级、简洁、现代”这类无法检查的形容词。

先输出说明并等待我确认，不要开始写页面。
```

## 第四步：让 Agent 完成实现和浏览器检查

确认页面说明后，再把实现交给 Agent：

```
请先读取已经确认的页面说明，再完成个人主页。

要求：
- 先复用项目已有的组件和样式规则
- 使用我提供的真实内容和素材，不编造经历
- 不复制参考网站的品牌、文案、图片或源代码
- 适配桌面端和移动端
- 不跳过项目已有的测试、类型检查和安全检查
- 启动本地预览，在真实浏览器中检查页面和关键交互
- 发现问题后修复并重新检查
- 在报告中写明实际检查的页面、浏览器视口尺寸和交互状态

请直接修改项目文件，不要在聊天中让我复制大段代码。完成后报告修改文件、检查结果、截图和仍未验证的事项。
```

OpenAI 的前端工作流也强调：先读取现有项目，提供截图或设计说明，复用已有设计系统，并在真实浏览器和不同屏幕尺寸下进行视觉检查。

如果 Agent 没有浏览器工具，它不能只根据代码声称“视觉验收通过”。让它提供本地预览地址，列出需要人工检查的桌面端和移动端视口尺寸，以及需要点击、展开或提交的交互。你按清单打开页面并提供截图后，再让 Agent 根据截图继续判断和修改。

## 第五步：修改时描述偏差，不要指挥代码

第一版出来以后，不要只说“再高级一点”，也不必告诉 Agent 应该改哪一行代码。使用“保留什么、修改什么、怎样验收”的结构：

```
请继续修改当前页面。

保留：现有内容顺序、正文和主要配色。
修改：首屏图片太小；标题与正文层级不明显；移动端按钮过于拥挤。
边界：不要重写整个页面，不要更换字体，不要修改其他区块。
验收：重新检查桌面端和移动端，确认图片清晰、按钮不重叠、页面没有横向滚动。

修改后说明具体改了哪些文件，并提供新的浏览器检查结果。
```

这种表达比“你去改 CSS”更有效，因为你描述的是结果和范围，具体实现仍由 Agent 根据项目结构决定。

## 出现问题时，怎样把现象交给 Agent

### 图片不显示

```
当前页面的头像没有显示。请不要先改版式，先检查素材文件是否存在、文件名与大小写是否一致、引用路径是否正确，并在浏览器中确认资源成功加载。
```

### 样式没有生效

```
页面内容能显示，但颜色和布局与页面说明不一致。请检查样式文件或组件样式是否被正确加载、是否被其他规则覆盖。定位原因后只修复样式问题。
```

### 按钮没有反应

```
点击主要按钮没有反应。请检查按钮目标、交互逻辑和浏览器控制台错误。不要改按钮外观，修复后重新点击验证。
```

### 手机端错位

```
桌面端基本正常，但移动端存在内容溢出和按钮拥挤。请只检查响应式布局，在窄屏浏览器中修复并重新截图，不要改变桌面端已经确认的结构。
```

重点是提供可观察的现象、限制修改范围，并要求 Agent 修复后再次验证。

## 完成后，你应该看什么

不要只接受一句“已经完成”。最终报告至少应让你确认：

* 页面是否使用了你的真实内容；
* Agent 实际创建或修改了哪些文件；
* 桌面端和移动端是否都检查过；
* 导航、链接、按钮和表单是否实际操作过；
* 图片、样式和脚本是否成功加载；
* 浏览器控制台是否存在错误；
* 项目原有的测试和检查是否通过；
* 哪些事项仍未验证，需要你人工确认。

有浏览器截图时，直接对照截图检查文字、层级、留白、图片裁切和移动端排列。网页能运行只是最低条件，页面是否准确表达你的内容仍然由你判断。

如果报告没有写出实际视口尺寸、触发过的交互或截图证据，只能说明代码检查结束，不能说明视觉验收已经完成。没有自动浏览器能力时，应由 Agent 给出人工检查清单，并等待你返回截图或问题描述。

## 上线之前，让 Agent 做公开检查

部署方式会随项目技术和托管平台变化，不要背固定点击流程。让 Agent 先检查项目，再依据托管平台当前的官方文档带你操作。

```
请先检查当前个人主页是否适合公开部署。

重点检查：
- 项目中是否包含密码、API Key、私人地址或不应公开的文件
- 图片、字体和其他素材是否有使用权限
- 页面在本地是否能正常构建和运行
- 资源路径在部署后是否仍然有效
- 项目适合使用哪种托管方式

先报告风险和建议，不要直接发布。等我确认平台、账号、仓库和公开范围后，再按照该平台当前的官方文档一步一步执行。
```

纯静态项目可以考虑 GitHub Pages，但仍应由 Agent 根据项目结构和 GitHub 当前文档确认发布方式。账号权限、仓库公开范围和域名购买等外部操作，需要由你明确确认。

## 这些内容暂时不用学

为了让 Agent 做出第一版个人主页，你暂时不需要：

* 背诵 HTML 标签；
* 记忆 CSS 属性和值；
* 亲自写 JavaScript 事件；
* 为了“显得专业”安装复杂框架；
* 看懂 Agent 生成的每一行代码。

等到 Agent 反复无法解决某一类问题，或者你希望亲自控制实现细节时，再针对那一小块深入学习。现在更重要的是先建立正确的协作方式：**你定义内容、目标、边界和验收，Agent 负责实现、检查和报告。**
