# 网页视觉词典：布局、页面结构、导航与常用组件

让 Agent 做网页时，“高级”“简洁”“有设计感”都很难直接执行。更准确的表达是：页面采用什么布局、内容按什么顺序出现、用户怎样移动、操作后怎样获得反馈。

这篇词典的目的不是让你学习实现代码，而是帮你看懂常见视觉词汇，并知道应该在什么情况下使用它们。

## 先分清四类词汇

| 类别                  | 它回答的问题            | 例子                                |
| ------------------- | ----------------- | --------------------------------- |
| 页面布局 Layout         | 内容在屏幕上怎么排         | 卡片式、分屏、网格、侧边栏                     |
| 页面结构 Page Structure | 用户先看到什么，接着看到什么    | Hero、功能区、案例研究、FAQ、页脚              |
| 导航 Navigation       | 用户怎样移动、跳转和切换      | 顶部导航、面包屑、标签页、分页                   |
| 组件 UI Components    | 用户怎样点击、输入、展开和获得反馈 | Modal、Drawer、Accordion、Toast、Form |

同一个页面会同时使用这几类词。例如，一个落地页可以采用分屏布局，开头使用 Hero，通过固定导航跳转，并用表单完成提交。

## 页面布局 Layout

布局描述内容占据屏幕的方式。卡片式、Bento 和分屏属于视觉组织方式；CSS Grid 与 Flexbox 则是实现布局的技术机制，不是固定的视觉风格。[MDN 的 CSS 布局说明](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/CSS_layout)

| 术语                       | 是什么、会产生什么效果                    | 适合什么内容             | 使用时注意什么                                                                                                                                                       |
| ------------------------ | ------------------------------ | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 卡片式布局 Card-based Layout  | 把内容拆成边界相对独立、可以重复排列的模块          | 项目列表、文章列表、商品、功能介绍  | 卡片过多会让所有内容看起来同样重要，应通过尺寸和内容密度建立主次                                                                                                                              |
| 瀑布流 Masonry Layout       | 模块宽度相近但高度不同，纵向错落排列             | 摄影、插画、灵感墙、不同宽高比的作品 | 不适合必须按行阅读或严格比较的数据；视觉顺序与内容顺序要保持可理解                                                                                                                             |
| 便当盒布局 Bento Grid         | 一种非正式设计名称，用大小不同的矩形模块建立层级       | 产品首页、创作者主页、功能总览    | 重点在尺寸差异表达主次，不是把页面随意切成许多格子                                                                                                                                     |
| 分屏布局 Split-screen Layout | 把主要区域分成两个并列部分，常见为文字与视觉并排       | 登录页、产品介绍、作品开场、对比内容 | 窄屏通常需要重新决定上下顺序，不能只把两边等比例缩小                                                                                                                                    |
| CSS Grid                 | 同时控制行和列的二维布局机制                 | 页面骨架、复杂模块、非对称网格    | 它是实现方法，不代表页面必须长成规则方格。[MDN：CSS Grid](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Grid_layout/Basic_concepts)                                       |
| Flexbox                  | 主要沿一行或一列分配空间、对齐和排序的一维布局机制      | 导航、按钮组、工具栏、卡片内部    | 适合处理一个主要方向；同时处理复杂行列关系时通常更适合 Grid。[MDN：Flexbox](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/CSS_layout/Flexbox)                        |
| 侧边栏布局 Sidebar Layout     | 一侧放长期可见或相对稳定的内容，另一侧放主体         | 文档、博客、后台、筛选页面      | 屏幕变窄时通常需要折叠、移到顶部或变成抽屉，避免挤压正文                                                                                                                                  |
| 仪表盘布局 Dashboard Layout   | 将导航、工具栏、指标、图表、表格和任务区组合成高信息密度界面 | 数据产品、管理后台、内容系统     | 应围绕任务和优先级组织，不要把营销首页误做成数据面板                                                                                                                                    |
| 响应式布局 Responsive Layout  | 页面根据可用空间、设备能力和内容需要重新排列         | 面向多种屏幕的网页          | 不是准备几个固定版本，也不是整体缩小；应在内容开始拥挤或断裂的位置调整。[MDN：Responsive design](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/CSS_layout/Responsive_Design) |
| 全出血布局 Full-bleed Layout  | 图片、颜色或视频突破普通内容容器，一直延伸到视口边缘     | 品牌首屏、摄影、章节过渡、沉浸式视觉 | 正文通常仍需要可读宽度；背景上的文字必须保持清晰对比                                                                                                                                    |

### 容易混淆的地方

* **卡片式与 Bento**：卡片式强调重复与整齐，Bento 强调不同模块的层级差异。
* **Grid 与 Flexbox**：Grid 适合同时考虑行列，Flexbox 适合沿一个主要方向排列；二者经常组合使用。
* **响应式与手机端**：响应式不只是增加一个手机版本，而是让内容在不同可用空间下持续可用。
* **布局与页面结构**：分屏描述“怎么排”，Hero 描述“这个区域承担什么任务”。

## 页面结构 Page Structure

页面结构描述内容分段和阅读顺序。结构词通常关注信息任务，而不是具体颜色或技术实现。HTML 中的 header、nav、main、section、article、aside 和 footer 也用来表达不同区域的语义职责。[MDN 的文档结构说明](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Structuring_content/Structuring_documents)

| 术语                        | 是什么、会产生什么效果                 | 适合什么内容              | 使用时注意什么                                 |
| ------------------------- | --------------------------- | ------------------- | --------------------------------------- |
| 单页网站 Single-page Website  | 主要内容集中在同一个页面，通过滚动或页内跳转浏览    | 活动介绍、简短作品集、信息量有限的官网 | 内容增长后会变得过长；独立主题和需要分享的网址可能更适合拆页          |
| 多页网站 Multi-page Website   | 不同主题拥有独立页面和网址，共享导航和视觉系统     | 企业官网、内容站、博客、成熟作品集   | 需要清晰的信息架构、页面层级和当前导航状态                   |
| 落地页 Landing Page          | 围绕一个主要目标组织信息，逐步引导用户采取行动     | 注册、预约、下载、购买、活动报名    | 每个区块都应服务于目标，避免加入抢夺注意力的无关入口              |
| 案例研究页 Case Study Page     | 按背景、问题、过程、决策、结果和复盘讲清一个项目    | 设计、开发、产品和品牌案例       | 不要只展示最终图片；过程和结果应有真实材料支持                 |
| 首屏 Hero Section           | 页面开头最受关注的区域，用来快速说明主题、价值和下一步 | 首页、产品页、活动页、落地页      | Hero 不是“大图”的同义词；它首先要让用户理解页面在讲什么         |
| 功能网格 Feature Grid         | 用一组并列模块概括能力、功能、服务或优势        | 产品功能、服务说明、能力介绍      | 项目过多或说明过长会失去可扫读性；同组项目应保持同一层级            |
| 固定叙事区 Sticky Storytelling | 一部分内容保持可见，另一部分随滚动推进不同阶段     | 产品原理、案例过程、品牌故事      | 滚动行为较复杂，窄屏和减少动态效果的偏好需要单独处理              |
| 时间线 Timeline              | 按时间或阶段展示事件与进度               | 经历、版本、里程碑、学习路径      | 没有明确时间或顺序关系的内容，不必强行使用时间线                |
| 常见问题区 FAQ Section         | 集中回答高频疑问，常与折叠组件配合           | 服务、价格、流程、产品和课程说明    | 问题应来自真实疑虑；FAQ 是内容区，Accordion 是可能使用的交互组件 |
| 页脚 Footer                 | 页面或网站的收尾区域，放置全局或次要信息        | 完整网站和长页面            | 通常承载联系方式、政策、次要导航等，不应成为无序链接仓库            |

### 容易混淆的地方

* **单页网站与落地页**：单页描述页面数量，落地页描述目标；一个落地页可以是单页，也可以属于多页网站。
* **Hero 与 Banner**：Hero 承担页面开场与信息任务，Banner 更常表示横幅式通知、推广或视觉区域。
* **FAQ 与 Accordion**：FAQ 是内容类型，Accordion 是展开和收起内容的交互方式。
* **页面结构与 HTML 标签**：设计结构描述内容任务，HTML 语义负责把这种任务表达给浏览器和辅助技术，二者相关但不是一回事。

## 导航与切换 Navigation

导航帮助用户理解当前位置、可以去哪里，以及操作后内容怎样变化。导航方式应与内容层级和任务频率匹配。

| 术语                      | 是什么、会产生什么效果            | 适合什么内容           | 使用时注意什么                                                                                                  |
| ----------------------- | ---------------------- | ---------------- | -------------------------------------------------------------------------------------------------------- |
| 固定导航 Sticky Navbar      | 页面滚动后仍保持可见的顶部导航        | 长页面、文档、需要频繁切换的站点 | 会占用视口空间，并可能遮住页内跳转后的标题                                                                                    |
| 汉堡菜单 Hamburger Menu     | 用菜单按钮收纳导航，点击后再展开       | 小屏界面、导航空间不足的页面   | 图标含义不能只靠外形猜测，应有可理解的名称和明确开关状态                                                                             |
| 面包屑 Breadcrumb          | 按层级显示当前页面的上级路径         | 文档、电商、内容分类、多层网站  | 它补充而不是替代主导航；不适合没有层级关系的页面。[WAI-ARIA APG：Breadcrumb](https://www.w3.org/WAI/ARIA/apg/patterns/breadcrumb/) |
| 锚点跳转 Anchor Link        | 跳到当前页面中的指定区块           | 长文章、单页网站、页内目录    | 固定导航存在时要避免目标标题被遮挡，并让跳转后的焦点和位置可理解                                                                         |
| 标签切换 Tabs               | 在同一内容区域切换同等级面板         | 设置、分类视图、相关数据面板   | 不适合表示前后步骤或不同页面层级；键盘和选中状态要清楚。[WAI-ARIA APG：Tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)          |
| 侧边导航 Sidebar Navigation | 将主要或分组导航长期放在页面一侧       | 后台、设置、文档、复杂工具    | 入口过多时需要分组和层级；窄屏通常需要转成其他形式                                                                                |
| 超级菜单 Mega Menu          | 展开大面积、多列的导航面板，集中展示复杂分类 | 产品矩阵、资源中心、大型内容站  | 分类逻辑必须清楚；较少的导航项没有必要使用                                                                                    |
| 底部导航 Bottom Navigation  | 在移动界面底部保持核心入口          | 高频切换的移动 Web 应用   | 只应保留最重要的同级入口，并避免遮挡页面操作和系统安全区域                                                                            |
| 分页 Pagination           | 把长列表分成多个页面，通过页码或前后入口移动 | 搜索结果、文章归档、数据列表   | 用户刷新、分享或返回时应能理解当前页；无限滚动是另一种取舍                                                                            |
| 返回顶部 Back to Top        | 在长页面中快速回到开头            | 长文章、长列表、长详情页     | 页面不长时没有必要；按钮不能遮挡正文或其他重要操作                                                                                |

### 容易混淆的地方

* **Tabs 与导航链接**：Tabs 切换同一上下文里的同级内容，导航链接通常前往另一个页面或明确位置。
* **面包屑与历史记录**：面包屑表达网站层级，不等于用户刚才实际访问过的页面顺序。
* **汉堡菜单与 Drawer**：汉堡菜单是触发导航的按钮或模式，Drawer 是内容展开时使用的面板形式。
* **分页与无限滚动**：分页提供明确页边界，无限滚动强调连续浏览，选择取决于查找、返回和比较需求。

## 常用组件 UI Components

组件是页面中可以重复使用的局部界面单元。名称只说明交互模式，不保证实现天然可访问；键盘操作、焦点、标签、状态和错误反馈仍需要在实现中检查。[WAI-ARIA Authoring Practices 组件模式](https://www.w3.org/WAI/ARIA/apg/patterns/)

| 术语                            | 是什么、会产生什么效果                | 适合什么内容             | 使用时注意什么                                                                                                             |
| ----------------------------- | -------------------------- | ------------------ | ------------------------------------------------------------------------------------------------------------------- |
| 模态框 Modal                     | 覆盖当前页面并暂时阻止背景交互的对话框        | 确认、登录、必须先完成的短任务    | 打开后需要管理键盘焦点，关闭后返回触发位置；不适合承载过长流程。[WAI-ARIA APG：Modal Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) |
| 抽屉 Drawer                     | 从屏幕边缘滑入的面板，背景页面仍作为上下文可见    | 移动导航、筛选、购物车、详情预览   | 要明确它是临时覆盖还是长期并列；关闭方式和背景交互必须一致                                                                                       |
| 手风琴 Accordion                 | 一组纵向标题控制对应内容的展开与收起         | FAQ、课程目录、分组说明、移动菜单 | 标题本身必须可操作，展开状态要清楚；不要隐藏用户必须同时比较的内容                                                                                   |
| 气泡提示 Tooltip                  | 在悬停或键盘聚焦时出现的简短补充说明         | 图标名称、术语解释、数据提示     | 不能承载完成任务所必需的信息，也不能只支持鼠标悬停                                                                                           |
| 轻提示 Toast                     | 操作后出现的非阻断状态消息              | 保存、复制、发布、网络状态反馈    | 重要错误和需要处理的决定不能快速消失；不要只用颜色表达状态                                                                                       |
| 轮播图 Carousel                  | 在有限区域依次显示一组内容              | 精选项目、产品截图、评价       | 自动播放容易抢夺注意力；需要清楚的切换、暂停、当前位置和键盘操作                                                                                    |
| 图片灯箱 Lightbox                 | 在覆盖层中放大查看图片或媒体             | 摄影、插画、商品图、项目截图     | 要提供关闭和切换方式，并保留标题、替代文字等上下文                                                                                           |
| 表单 Form                       | 由标签、输入控件、选择、校验和提交反馈组成的任务区域 | 登录、搜索、联系、报名、设置     | 标签、必填、错误、提交中和成功状态都要清晰，失败时不应无故丢失输入                                                                                   |
| 命令面板 Command Palette          | 通过搜索和键盘快速找到页面或执行命令的浮层      | 文档、开发工具、复杂后台、效率产品  | 是高频用户的快捷入口，不应成为唯一的导航方式                                                                                              |
| 悬浮操作按钮 Floating Action Button | 固定在界面角落、强调主要操作的按钮          | 创建、添加、编辑等高频核心操作    | 页面没有单一主要操作时不宜使用；不能遮挡底部导航和内容                                                                                         |

### 容易混淆的地方

* **Modal 与 Drawer**：Modal 强制用户先处理当前对话，Drawer 更常保留背景上下文并承载导航、筛选或详情。
* **Accordion 与 Tabs**：Accordion 沿纵向展开不同区块，Tabs 在同一位置切换同级面板。
* **Tooltip 与 Toast**：Tooltip 解释一个控件，Toast 反馈一个已经发生的操作。
* **Lightbox 与 Modal**：Lightbox 是以查看媒体为核心的覆盖层，可以视为更具体的展示模式；Modal 的任务范围更广。
* **表单与 Modal**：表单是输入任务，可以直接出现在页面中，也可以被放进 Modal；它们不是同一类别。

## 怎样把词汇交给 Agent

术语的作用是减少猜测，不是把多个流行组件全部塞进页面。描述需求时，可以使用这个结构：

```
使用什么：选择一个布局、页面结构、导航或组件名称。
解决什么：说明它承载的真实内容或用户任务。
怎样变化：说明在窄屏、展开、关闭、加载和错误状态下的行为。
不能怎样：说明不希望复制的风格、无关组件和交互边界。
怎样验收：说明要检查的页面、状态、键盘操作和移动端结果。
```

例如，不要只说“加一个 Modal”，而要说明它是查看详情、填写表单还是确认删除；不要只说“使用 Bento”，而要说明哪个内容最重要、哪些模块属于次要信息。

## 选择词汇时的基本原则

* 从内容和任务出发，不从流行效果出发；
* 一个组件只解决一个清楚的问题；
* 先确定信息层级，再决定卡片、网格和动效；
* 桌面端选择不能直接照搬到移动端；
* 交互组件必须检查键盘、焦点、标签、状态和错误反馈；
* 看不出用途的组件，即使流行也不必加入。

你不需要记住所有英文名称。真正有用的是理解差异：它是负责排列、组织内容、帮助移动，还是处理一次具体操作。理解到这个程度，就足以让 Agent 更准确地实现页面。
