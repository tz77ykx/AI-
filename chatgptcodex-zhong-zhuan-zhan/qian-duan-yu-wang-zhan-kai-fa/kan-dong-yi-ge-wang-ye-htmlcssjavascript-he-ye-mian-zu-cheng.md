# 看懂一个网页：HTML、CSS、JavaScript 和页面组成

使用 Agent 做网站时，你不需要先学会手写网页，但需要知道一个网页由哪些部分组成、每一部分负责什么。

这些知识的用途不是让你背语法，而是帮助你理解 Agent 的说明，判断问题大概出现在哪一层，并把修改要求说清楚。

## 网页、网站和 Web 应用有什么区别

* **网页**：浏览器中打开的一个页面，例如文章页、产品介绍页或登录页。
* **网站**：通常由多个网页及它们之间的导航关系组成。
* **Web 应用**：更强调操作和数据变化，例如在线文档、邮箱或后台系统。

三者的侧重点不同，但浏览器最终仍然需要处理页面结构、样式、交互逻辑和各种素材。

## 先把网页理解成几个协作层

| 部分               | 主要负责什么         | 你能看到的效果                 |
| ---------------- | -------------- | ----------------------- |
| HTML 或页面组件       | 内容、层级和语义结构     | 标题、正文、图片、链接、按钮、表单和页面区块  |
| CSS 或样式系统        | 外观、排版和不同屏幕下的布局 | 颜色、字体、间距、对齐、大小、动画和响应式变化 |
| JavaScript 或交互逻辑 | 行为、状态和数据处理     | 菜单展开、弹窗、筛选、表单反馈和内容动态更新  |
| 素材与数据            | 页面实际使用的内容资源    | 图片、图标、字体、视频、文章、商品或接口数据  |

它们不是互相替代的关系。同一个按钮通常需要 HTML 提供结构、CSS 决定外观、JavaScript 处理点击后的行为。

## HTML 负责页面的内容和结构

HTML 是网页内容的基本结构。浏览器会读取 HTML，理解哪些内容是标题、段落、导航、图片或表单。页面长什么样主要由 CSS 决定，页面怎样响应操作主要由 JavaScript 决定。[MDN 对 HTML 的说明](https://developer.mozilla.org/en-US/docs/Web/HTML)

### 一个 HTML 文档最外层有哪些部分

可以把 HTML 文档理解成下面这棵结构树：

```
HTML 文档
├── 文档声明：告诉浏览器按照现代 HTML 规则处理页面
└── html：整个网页的根
    ├── head：页面设置和给浏览器看的信息
    └── body：用户在页面中看到和操作的内容
```

#### head：页面设置区

`head` 中的内容通常不会直接作为正文显示。它主要保存：

| 内容       | 负责什么                 | 常见效果            |
| -------- | -------------------- | --------------- |
| 页面标题     | 定义页面名称               | 显示在浏览器标签页和收藏记录中 |
| 字符编码     | 告诉浏览器怎样解释文字          | 避免中文等字符显示异常     |
| 视口设置     | 告诉浏览器怎样适配移动设备        | 影响手机上的页面宽度和缩放   |
| 页面说明等元信息 | 描述页面内容               | 可供搜索、分享和其他系统读取  |
| 样式文件连接   | 告诉浏览器去哪里加载 CSS       | 让页面获得排版与视觉样式    |
| 脚本连接     | 告诉浏览器加载哪些 JavaScript | 为页面提供交互和数据逻辑    |

#### body：可见内容区

`body` 里放的是页面主体。标题、段落、图片、导航、按钮、表单和页脚等，通常都属于这里。

`head` 和 `body` 的区别可以简单记成：**前者描述和配置页面，后者承载用户看到与操作的内容。**

## body 里常见的页面区块

HTML 不只表示某一段文字或某一张图片，还可以表示页面区域的职责。使用有明确含义的结构有助于浏览器和辅助技术理解内容。[MDN 的文档结构说明](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Structuring_content/Structuring_documents)

| 页面区块    | 主要职责           | 常见内容                |
| ------- | -------------- | ------------------- |
| header  | 页面或内容区块的开头     | Logo、站点名称、标题、简介     |
| nav     | 主要导航           | 首页、栏目、产品、关于、登录入口    |
| main    | 当前页面最主要、最独有的内容 | 文章正文、产品信息、搜索结果、操作界面 |
| section | 按主题或功能划分内容     | 功能介绍、案例、常见问题、联系方式   |
| article | 可以相对独立理解的内容    | 一篇文章、一条新闻、一张帖子      |
| aside   | 与主体有关但不是主线的信息  | 相关文章、补充说明、作者信息      |
| footer  | 页面或区块的结尾       | 联系方式、版权说明、政策链接、次要导航 |

这些名字表达的是内容作用，不直接决定它们出现在左边、右边还是顶部。具体位置、颜色和大小仍由 CSS 控制。

## 页面中常见的内容元素

| 元素类型  | 它表达什么        | 页面上的常见效果       |
| ----- | ------------ | -------------- |
| 标题    | 内容层级和主题      | 不同级别的栏目标题、文章标题 |
| 段落    | 连续文字内容       | 正文、介绍、说明       |
| 链接    | 前往另一个地址或页面位置 | 点击后跳转          |
| 图片    | 视觉内容         | 照片、插图、截图、商品图   |
| 列表    | 一组有关系的项目     | 导航、步骤、功能点、目录   |
| 按钮    | 触发一个操作       | 提交、打开、保存、删除、切换 |
| 表单    | 收集用户输入       | 登录、搜索、联系、报名、筛选 |
| 音频和视频 | 播放媒体内容       | 播放器、字幕和控制按钮    |
| 表格    | 表示行列关系明确的数据  | 参数对比、记录、统计结果   |

链接和按钮看起来可以很像，但作用不同：链接主要负责去往某处，按钮主要负责触发操作。外观相似不代表结构职责相同。

## CSS 负责网页看起来怎样

CSS 是样式语言，用来控制 HTML 内容的呈现方式。[MDN 对 CSS 的说明](https://developer.mozilla.org/en-US/docs/Web/CSS)

CSS 常见的职责包括：

* **颜色**：背景色、文字色、边框色和状态色；
* **字体**：字体家族、字号、字重、行高和字间距；
* **间距**：内容内部留白、区块之间的距离；
* **尺寸**：宽度、高度、最大宽度和图片比例；
* **布局**：上下、左右、网格、对齐和元素顺序；
* **装饰**：圆角、边框、阴影、渐变和透明度；
* **状态**：鼠标悬停、获得焦点、禁用和错误状态；
* **响应式**：根据屏幕宽度和设备特点调整排列与尺寸；
* **动效**：过渡、进入、离开和状态变化。

因此，“文字内容不对”和“文字太小”是两类问题：前者通常属于 HTML 或数据，后者通常属于 CSS。

### 什么是响应式

响应式不是把桌面页面整体缩小，而是让页面根据可用空间重新安排内容。例如，多列内容在窄屏上改为单列，导航收进菜单，图片宽度跟随容器变化。[MDN 的响应式设计说明](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/CSS_layout/Responsive_Design)

如果桌面端正常、手机端出现横向滚动、文字被裁切或按钮拥挤，通常需要检查响应式样式。

## JavaScript 负责网页怎样变化和回应

JavaScript 是脚本语言，常用于处理页面行为、状态和数据。[MDN 对 JavaScript 的说明](https://developer.mozilla.org/en-US/docs/Web/JavaScript)

它常见的职责包括：

* 监听点击、输入、滚动和键盘操作；
* 打开或关闭菜单、弹窗和折叠区域；
* 检查表单输入并显示反馈；
* 根据用户选择更新页面内容；
* 从服务器获取数据并展示结果；
* 记录当前选中项、登录状态或操作进度；
* 控制需要逻辑判断的复杂动画。

并不是所有视觉变化都需要 JavaScript。简单的颜色变化、布局调整和部分动画可以由 CSS 完成。只有涉及操作逻辑、状态或动态数据时，JavaScript 的作用才更明显。

## 图片、图标、字体和数据属于素材层

网页除了代码，还需要实际资源：

| 资源        | 常见用途            | 容易出现的问题               |
| --------- | --------------- | --------------------- |
| 图片        | 首图、头像、产品图、背景图   | 文件太大、裁切不对、路径错误、缺少替代文字 |
| 图标        | 表示操作或状态         | 含义不清、风格不统一、加载失败       |
| 字体        | 建立文字气质和层级       | 字体未加载、字重缺失、中文回退效果不同   |
| 视频和音频     | 演示、课程、背景媒体      | 加载慢、自动播放限制、移动端兼容问题    |
| 本地数据或接口数据 | 提供文章、商品、用户信息等内容 | 请求失败、字段缺失、加载状态没有处理    |

素材不是最后随便填进去的装饰。图片比例、文字长度和数据结构都会影响页面布局。

## 文件、文件夹和路径为什么重要

网页需要知道样式、脚本和图片在哪里，这个位置关系由路径表示。

* **项目根目录**：整个项目最外层的文件夹，不一定等同于网站发布后的根地址。
* **相对当前文件的位置**：例如从当前页面附近寻找图片或样式；页面位置变化时，解析结果可能跟着变化。
* **相对网站根地址的位置**：以 `/` 开头，从当前网站的根地址寻找资源，不受当前页面层级影响。
* **完整 URL**：包含协议和域名，例如指向另一个网站上的资源。
* **资源目录**：集中存放图片、字体或其他静态文件。

文件被移动、改名，或者大小写与引用不一致时，页面可能仍能显示文字，但图片、样式或脚本会加载失败。

框架项目的目录名称可能不同。有的项目使用 `src`、`public`、`assets` 或组件目录，因此不能只凭文件名猜职责，应先读取项目结构和说明。

## 浏览器怎样把这些部分变成页面

用户打开网址后，浏览器会一边解析页面，一边发现和请求其他资源。许多资源请求可以并行发生；浏览器获得足够的结构和样式后就可以开始绘制，不一定等待图片、字体、脚本和数据全部完成。[MDN 的浏览器工作原理说明](https://developer.mozilla.org/en-US/docs/Web/Performance/Guides/How_browsers_work)

```
请求页面
  ↓
逐步解析 HTML，建立内容结构
  ├── 发现 CSS、脚本、图片和字体后发起请求
  ├── 根据已有结构与样式计算布局
  └── 条件满足时开始首次绘制
          ↓
后续资源和数据到达
  ↓
按需要更新结构、样式、布局或画面
  ↓
继续响应点击、输入和其他状态变化
```

这也解释了为什么页面可能先出现文字，随后图片、字体或数据才补上，以及为什么部分资源到达后布局还会变化。HTML 已经加载，不代表 CSS、图片或 JavaScript 也一定加载成功；页面能显示，也不代表交互和移动端布局都正确。

## 前端框架改变了文件组织，没有改变基本职责

在原生网页里，你可能直接看到 HTML、CSS 和 JavaScript 文件。在 React、Vue、Next.js 等项目中，结构、样式和交互可能被拆进多个组件，或者写在同一个组件文件的不同部分。

文件形式变了，但问题仍然可以按照相同思路理解：

* 内容和层级由页面结构或数据决定；
* 视觉效果由样式系统决定；
* 操作和状态由交互逻辑决定；
* 图片、字体和数据仍然需要正确加载；
* 浏览器仍然负责最终呈现和执行。

所以面对陌生项目时，不要先要求 Agent “修改某个 HTML 文件”。先让它说明当前项目中哪些文件分别承担这些职责。

## 看到问题时，大概应该检查哪一层

| 你看到的现象        | 优先理解为哪一类问题         | 可以怎样告诉 Agent   |
| ------------- | ------------------ | -------------- |
| 标题、正文或内容顺序不对  | HTML、页面组件或数据       | 检查内容来源和页面结构    |
| 颜色、字号、间距或对齐不对 | CSS 或样式系统          | 只检查视觉样式，不改内容   |
| 按钮、菜单或表单没有反应  | JavaScript、事件或链接目标 | 检查交互逻辑和浏览器错误   |
| 图片或字体没有显示     | 素材文件、路径或网络加载       | 检查资源是否存在并成功加载  |
| 桌面正常、手机错位     | 响应式样式              | 检查窄屏布局和横向溢出    |
| 页面先空白，稍后才有内容  | 数据请求、加载状态或脚本       | 检查请求过程和加载反馈    |
| 页面能打开但速度很慢    | 图片、字体、脚本、数据或渲染过程   | 检查资源体积、请求和性能记录 |

这张表只是帮助定位方向，不代表问题一定只来自某一层。最终仍要让 Agent 检查实际项目和浏览器结果。

## 你不需要学到什么程度

如果你的目标是让 Agent 帮你完成网页，你暂时不需要背诵标签、CSS 属性或 JavaScript 语法。

你需要达到的是“能看懂职责”的程度：

* 知道 `head` 是页面设置区，`body` 是可见内容区；
* 知道 header、nav、main、section、article、aside 和 footer 表示什么页面区域；
* 知道 HTML 管内容结构，CSS 管呈现，JavaScript 管行为和状态；
* 知道图片、字体和数据需要通过正确路径或请求加载；
* 知道浏览器检查是判断网页是否真正完成的依据。

理解这张知识地图以后，你就能听懂 Agent 在说什么，也能把“哪里不对”描述得更准确，而不需要亲自编写代码。
